# 底部渐变模糊通用设计规范（BottomGradientBlurVeil）

> **已废弃（LiquidTab 2.0）**：底部渐变模糊现已全局关闭。本文件仅供理解历史实现与旧代码，不是当前效果规范；禁止新适配引用或重新启用，除非用户明确要求恢复。

> 参考实现：微信聊天页底部渐变模糊（`GlassHostLayout.updateWechatGradientBlur` / `applyWeChatGradientBlur`）。
> 历史说明：本规范曾将其提炼为通用设计接口。当前版本不得据此为新 APP 接入底部渐变模糊。

---

## 1. 接口契约

```
BottomGradientBlurVeil(host: View, contentTarget: View, logTag: String)
    update(active: Boolean)   // 每帧 preDraw 调用；active = 当前页面需要模糊遮罩
    clear()                    // 页面切换/宿主销毁时调用
```

- `host`：液态底栏宿主（`GlassHostLayout`），作为 zone 上边界锚点。
- `contentTarget`：页面内容根视图（`android.R.id.content` 下面积最大的全屏子分支，排除 LiquidTab 自身注入的视图）。**效果树直接 `setRenderEffect` 在该视图上**。
- Zone 定义（目标视图本地坐标系）：`[液态底栏顶边, 屏幕底边]`。

## 2. 防闪烁四不变量（核心，违反任意一条即出现闪烁）

1. **直渲管线，禁止快照**：效果树用 `setRenderEffect` 直接挂在内容根视图上，GPU 每帧对实时内容重渲染。软件位图采样滞后于滚动；RenderNode 重录每次都会丢弃 GPU 滤镜缓存——两者都表现为底部模糊闪烁/脱节。
2. **≥3px 迟滞重建**：仅当 zone 几何（宽/高精确，top/bottom 漂移 ≥3px）变化时才重建效果树。`getLocationInWindow` 整数读数每帧抖动 ±1px，重建会重置 shader uniform 快照并丢弃滤镜缓存，读作"模糊半径跳动"；≤3px 的 zone 漂移被顶部快速淡出带完全掩盖，不可见。
3. **缓存抗瞬断**：探测信号（目标视图、WebView 边沿、折叠栏位置等）瞬时丢失时**保留上一次读数**。回落到默认值再跳回（数百像素往返）是最严重的闪烁源。
4. **MIRROR 而非 CLAMP**：所有带的 `createBlurEffect` 必须用 `TileMode.MIRROR`。列表底边以下无内容可采样，CLAMP 会把最后一行像素拉伸成条纹喂给模糊；拖动时行流过该边，强半径带把它放大成底边抖动。MIRROR 采样边缘内真实内容的镜像，与内容同速滚动。

## 3. 带参数表（六带渐进，最弱在前/最强在后，SRC_OVER 叠加）

| 带 | 半径 (dp) | fadeT | solidT |
|----|-----------|-------|--------|
| 1 | 3.5 | 0.00 | 0.30 |
| 2 | 6 | 0.10 | 0.45 |
| 3 | 10 | 0.22 | 0.60 |
| 4 | 15 | 0.35 | 0.75 |
| 5 | 22 | 0.50 | 0.88 |
| 6 | 32 | 0.62 | 1.00 |

- 结构：passthrough 基底 → 每带 = [梯度遮罩 RuntimeShader 链接 平台高斯(MIRROR)] → 与累积结果 `createBlendModeEffect(acc, band, SRC_OVER)`。
- **顺序不可颠倒**：SRC_OVER 合成时后画的带在上层；若最强带在前，会被最弱带的不透明区掩埋，整片渲染成最小半径。
- 每带遮罩：`t = clamp((coord.y - zoneTop)/zone, 0, 1)`，`a = smoothstep(fadeT, solidT, t)`，输出 `c * a`（保持预乘以配合 SRC_OVER）。

## 4. 色罩页（WebView 类页面，如贴吧"小卖部"、哔哩哔哩"会员购"）

WebView 表面异步且止于原生底栏旧边沿，模糊不确定 → 使用**确定性色罩**（`MODE_COLOR_VEIL`）：

- 渐变：底栏顶边（全透明）→ WebView 内容边沿（全不透明，6 段 0/18/64/150/230/255 alpha，位置 0/0.22/0.45/0.68/0.88/1.0），CLAMP 使不透明色一直延伸到屏幕底（手势区防原生像素泄漏）。
- 边沿读数必须走 `CachedContentEdge`：探测节流 ≥250ms、≥3px 迟滞、瞬断保缓存。
- 模糊页与色罩页切换时必须 `clear()` 掉上一模式的效果。

## 5. 接入清单

安装侧：`GlassInstaller.findFullWindowContentBranch(content, navigation)` —— 从 navigation 向上走到 `android.R.id.content` 的直接子分支（回退：首个全窗子分支），作为 contentTarget 传入 `GlassHostLayout(bottomVeilSource = …)`；控制器在宿主构造时创建，preDraw 中 `bottomGradientVeil.update(bottomVeilWantsBlur(shouldShow))` 驱动，detach 时 `clear()`。

### 5.2 特殊路径（历史遗留，仍符合四不变量）

- 微信：聊天页 `updateWechatGradientBlur`（参考实现本体），通讯录色罩 ViewOverlay。
- 百度贴吧：`TiebaBottomBlurOverlay` 持有控制器（首页/我的模糊、进吧/小卖部色罩、消息全清）。
- 哔哩哔哩 会员购：`BilibiliBottomVeil` 独立 View 绘制色罩，边沿走 `CachedContentEdge`。

### 5.3 接入要点

1. 模糊页与色罩页切换时必须 `clear()` 上一模式的效果（`update(false)` 即触发）。
2. veil View 只负责绘制色罩；模糊路径不持有任何 View/RenderNode。
3. 液态底栏宿主不是 contentTarget 的后代，因此永不被模糊。
4. 深浅色：遮罩通道跟随底栏主题（`isDarkGlass()`），浅色=白通道，深色=黑通道。
5. 异步表面（WebView/Meco TextureView）分两类：**内容止于旧底栏边沿**的走色罩（边沿=不透明锚点）；**全窗填充**的（如拼多多促销页）直接直渲模糊——TextureView 参与视图层级渲染，祖先 RenderEffect 可正常模糊。

### 5.4 消息页底栏退出契约（滚动检测模式，微博/小红书/淘宝已接入）

适用：需要"消息 tab 无底栏沉浸"的 APP。当前接入：微博（消息页）、小红书（消息页）、淘宝（消息页）。

#### 设计意图

消息页内容密集、底部有操作区域，液态底栏常驻会遮挡内容。方案：当用户**停止滚动 1 秒**后底栏自动退出；用户**开始滚动**时底栏立即恢复。这比"固定延时退出"更自然——用户主动浏览时底栏始终在，停止交互后才退场。

#### 接口

```kotlin
// 统一字段（GlassHostLayout 内）
private val msgScrollHideRunnable: Runnable      // 1s 延迟触发
private var msgScrolledToStop: Boolean            // true = 底栏已隐藏
private var msgScrollListenerAttached: Boolean    // 确保只注册一次

// 驱动点：currentPageAllowsNavigation() 中
if (isMessageTab) {
    ensureMsgScrollStopHideListener()
    return !msgScrolledToStop  // false → 隐藏底栏
}
// 离开消息页时重置
if (msgScrolledToStop) {
    msgScrolledToStop = false
    removeCallbacks(msgScrollHideRunnable)
}
```

#### 实现细节

1. **监听方式**：`ViewTreeObserver.OnScrollChangedListener`（窗口级，不依赖特定 View 类型，不怕 RecyclerView 被混淆）。
2. **触发条件**：仅当宿主的 `selectedIndex` 匹配消息页索引时响应滚动事件，避免影响其他 tab。
3. **防抖**：每次滚动事件 → `removeCallbacks` + `postDelayed(1000ms)`，停止 1 秒后才触发隐藏。
4. **即时恢复**：`msgScrolledToStop = false` 在下一次滚动事件时立即设置，底栏在下一帧 preDraw 恢复。
5. **生命周期**：`OnScrollChangedListener` 注册在 `rootView.viewTreeObserver` 上，仅注册一次（`msgScrollListenerAttached` 标志）。Activity 销毁时自动回收。

| APP | 消息页索引 | 判定方式 |
|-----|-----------|---------|
| 微博 | 3（`WEIBO_MESSAGE_INDEX`） | `TabHost.getCurrentTab()` |
| 小红书 | 3（`XHS_MESSAGE_INDEX`） | 宿主 `selectedIndex` |
| 淘宝 | 2（`TAOBAO_MESSAGE_INDEX`） | 宿主 `selectedIndex` |

### 5.5 滚动安全距离（米家"我的"模式，小米运动健康已接入）

适用：页面为全高滚动容器（ScrollView/RecyclerView/NestedScroll），原生底栏移除后其自带的底部 inset 一并消失，末尾操作行会停在液态底栏下方。

处理（`adjustMiHealthScrollSafety`，移植自米家 `adjustMiHomeBottomActions` 的滚动 padding 段）：

1. 每 160ms 节流探测：找所有**跨过底栏顶边**的可见滚动容器（`rect.top < hostRect.top && rect.bottom > hostRect.top`）。
2. **只取最外层命中者**（`isDescendantOf` 过滤嵌套）。设备页教训：主滚动器内部还挂着多个分段 RecyclerView（`device_rv_tab_content` 等），滚动到末尾时它们也跨过底栏顶边；内外各补一份 padding 会叠加成末行下方的大片空白（双重 344px）。
3. **padding 按容器自身底边动态锚定**：`required = rect.bottom - (barTop - gap)`，并与 base 取 max。容器底边不在屏幕底边时按需缩小，不做"全屏高度"一刀切。
4. `clipToPadding = false` 让内容滚入 padding 区；首次记录原始 padding 为 base，只增不减，避免与 APP 自身 padding 设置互相覆盖。
5. **恢复路径**：缓存中不再命中的视图（页面切换/结构变化）要把 padding 还原为 base，否则陈旧 padding 永久残留。
6. 米家在"我的"页与"产品"页生效（产品页为 2026-09-03 用户要求扩展）；小米运动健康四个 tab 底栏常驻，故无条件全 tab 生效。

### 5.6 原生图标直绘（去 tint）

小米运动健康原先对图标做 SRC_IN tint（选中橙、未选中灰），遮罩异常。已改为**原生像素直绘**：`tintBySelection = false` 走快照原样绘制，选中/未选中状态由 APP 原生图标自带，液态滑块单独标记当前 tab。通用原则：原生图标已区分选中态的 APP（微信/B站/贴吧/小米运动健康）一律去 tint。


## 6. 已知禁止事项（历史教训）

- 禁止 `updateDisplayListIfDirty` + `RenderNode.beginRecording` 重录采样（贴吧/B站旧方案，滚动时闪烁的根因）。
- 禁止软件 draw + box blur（主线程滞后）。
- 禁止固定半径双环 taps 核 shader（产生重影，读不出高斯感）。
- 禁止把遮罩 uniform/zone 几何放在每帧重设的路径上（等价于每帧重建）。
- 隐藏原生底栏后，禁止保留其大高度布局占位：占位会被页面底色填充，并进入底部取样形成遮挡信息流的整块色带。也不能未经验证直接把原生容器设为 `GONE`；京东会因此丢失 presenter/native 生命周期并在数秒后重启。优先使用应用可接受的结构性回收方式；必须压缩高度时，仅在应用确实恢复高度后作一次条件修正，严禁无条件每帧写 setter。
- 相同背景帧上的外层玻璃、渐变底幕和滑块组合场景必须复用 RenderNode；只有输入位图、主题、尺寸或导航签名变化时才重录。滑块几何和光学参数可以逐帧更新，不能因此重复构建未变化的模糊背景。
